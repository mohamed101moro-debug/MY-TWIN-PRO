# جرد سطح API — My Twin P0.05

**التاريخ:** 2026-10-10
**المصدر:** فرع `integration/p0-05-baseline-2026-10-10` بعد استيراد P0.05
**النوع:** فحص ساكن للمصدر؛ ليس اختبار اختراق أو إثباتاً لتكوين Railway/Supabase وقت التشغيل.

## الخلاصة التنفيذية

| القياس | النتيجة |
|---|---:|
| تعريفات المسارات المكتشفة من decorators | 254 |
| ملفات/وحدات المسارات | 50 |
| المسارات المسجلة في الـ API registry | 216 |
| المسارات الداخلية المشروطة `admin` / `admin_routes` / `dev` | 23 |
| تعريفات المسارات غير الموصولة بالـ registry | 15 |
| المسارات التي يتضمن عنوانها `{user_id}` | 22 |

الأرقام جرد شيفرة. المسار غير المسجل ليس endpoint متاحاً من التطبيق الحالي، والمسار المشروط لا يصبح متاحاً إلا بعد اجتياز سياسة التسجيل الداخلية.

## الملكية وحدود الحساب

- من المسارات الـ22 التي تحمل `{user_id}`، تستخدم 20 مساراً `require_request_owner` صراحةً.
- `GET /api/projects/stats/{user_id}` يقارن قيمة المسار بالهوية المستخرجة من Bearer token، ويرجع 404 عند اختلافهما، ثم يقيد استعلام قاعدة البيانات بالهوية الموثقة. أضيف اختبارا انحدار لتثبيت السلوكين.
- `GET /api/admin/users/{user_id}` ضمن `/api/admin`؛ له مسار الحراسة الإدارية المنفصل ولا يُعامل كمسار مستخدم عادي.
- `memories` و`goals` و`projects` تعتمد الهوية الموثقة من الخادم في التدفقات المفحوصة، لا قيمة عميل غير موثوقة وحدها.
- وسيط الحوكمة العام يفحص Bearer token وحقول الملكية في query/body للمسارات المصنفة؛ لا يعتمد وحده لتأمين `user_id` الموجود في path. لذلك نُفحص هذا النمط منفصلاً أعلاه.

## نتائج المراجعة اليدوية للاستثناءات

أظهر فحص AST اثني عشر مساراً لا يلتقط لها الفاحص الحارس المباشر المعتاد. تمت قراءة المصدر وتصنيفها كما يلي:

| التصنيف | المسارات | الحكم الحالي |
|---|---|---|
| مصادقة عامة لازمة | `/api/auth/signup`, `/login`, `/forgot-password`, `/google` | متاحة دون جلسة بحكم الوظيفة؛ لا تتضمن بذاتها قراءة بيانات مستخدم آخر. يلزم اختبار معدل الطلب والتعداد والمخاطر التشغيلية ضمن بوابة الأمن المستقلة. |
| كتالوج عام | `/api/economy/pricing` | بيانات عرض عامة. |
| ميزات معطلة | `/api/economy/ad-reward`, `/api/economy/trial/start` | ترجع 410، ولا تمنح مكافآت/تجارب؛ يوجد اختبار للعقد. |
| هوية الكيان | `/api/v1/passport`, `/api/v1/fingerprint` | محمية عبر `get_current_canonical_user_id`، الذي يعتمد هوية Bearer موثقة ثم يتحقق من UUID. هذا استثناء كاذب في كشف أسماء الحراس. |
| إشعارات المتجر | `/api/billing/rtdn` | مغلقة افتراضياً بــ 503 حتى يجهز تحقق Google Pub/Sub/OIDC؛ لا تقبل تحديث استحقاق غير متحقق. |
| مهمة داخلية | `/api/system/consolidate` | تتطلب `CRON_SECRET_KEY` وheader مطابقاً؛ ترفض عند غياب السر. |
| حالة النظام | `/api/system/status` | عامة؛ تكشف أسماء المحركات والعدد وعمر آخر heartbeat عالمي. لا تكشف محتوى ذاكرة مستخدم مفرد، لكن يوصى بتقليل هذه البيانات أو نقل endpoint إلى مراقبة داخلية. |

سياسة `resolve_internal_routers` تمنع تسجيل واجهات التطوير والإدارة في `staging` و`production`، وتشترط `ENVIRONMENT=development` وأسراراً قوية ومختلفة للإدارة قبل تحميلها.

## وحدات غير موصولة

توجد 15 تعريفاً في وحدات لا يربطها الـ registry الحالي، ضمن `ai_trainer_routes`, `billing`, `perception_snapshot`, و`vision_routes`. لا تُعامل هذه الشيفرة كوظائف تشغيلية متاحة للمستخدمين حتى تُسجل عمداً وتُضاف لها اختبارات ملكية/إساءة استخدام وموافقة المنتج.

## الحدود والفحوص التالية

- لم يُجرَ DAST أو اختبار بصندوق أسود على نشر Railway، لأن إعدادات Railway لا يمكن قراءتها من هذه الجلسة.
- لا يثبت هذا المستند سياسات RLS الفعلية في قاعدة Supabase أو صلاحيات مفاتيح الإنتاج.
- لا تُغلق بوابة الأمن/الإطلاق بمجرد هذا الجرد؛ يلزم فحص RLS وسياسات التخزين، اختبارات تغيير الحساب بين A/B، اختبار rate limits، مسح الاعتماديات، وفحص سجلات الأسرار قبل النشر.
- حالة `/api/system/status` العامة تبقى بنداً لتحسين تقليل البيانات التشغيلية.
