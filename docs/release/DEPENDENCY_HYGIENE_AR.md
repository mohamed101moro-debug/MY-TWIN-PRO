# تنظيف اعتماديات العميل — 2026-10-11

## التغيير

أزيلت الاعتماديات المباشرة التالية من `package.json` و`package-lock.json`:

- `react-native-markdown-display`: لا يوجد استيراد أو استخدام من كود العميل؛ المكتبة الوحيدة ذات الاسم المشابه في المشروع هي تنسيق Markdown في backend ولا تعتمد عليها.
- `sentry-expo`: لا استيراد أو إعداد plugin لها. يحتفظ المشروع بـ `@sentry/react-native` كمسار Sentry المقصود، لكن تهيئته الفعلية ما زالت بنداً لمرحلة observability وليست مفعلة بهذا التغيير.
- `onesignal-expo-plugin`: لا استيراد له ولا إدراج في قائمة Expo plugins. حذف الإضافة لا يحذف تكامل OneSignal في backend؛ إرسال الخادم عبر REST مستقل. يبقى استقبال إشعارات العميل عبر `expo-notifications`.

اعتمد القرار على بحث كامل في شجرة المصدر وملف إعداد Expo، لا على نتيجة التدقيق وحدها. لم تُضف بدائل أو overrides قسرية، ولم تُغيّر إصدارات Expo أو React Native في هذا الفرع.

بعد التنظيف وإعادة إنشاء lockfile، أعاد `npm audit --omit=dev` **62 نتيجة: 24 متوسطة، 37 عالية، وواحدة حرجة**. انخفض الإجمالي عن 69، لكن بوابة CI عند `--audit-level=high` ما زالت تفشل. لا نعامل هذا التنظيف كعلاج للثغرات المتبقية.

## التحقق المطلوب

اجتاز clean install (`npm ci --legacy-peer-deps`)، وTypeScript، وJest، وAndroid bundle، و`expo install --check` بعد التغيير. ما زال `npm audit --omit=dev` يفشل بالأرقام أعلاه؛ تحديث SDK و/أو إصلاحات متوافقة لازمة لمعالجة بقية السلاسل عالية/حرجة.

## النطاق والقيود

هذا تنظيف dependency graph محدود. لم يغير أي سلوك في المنتج أو إعدادات push/Sentry، ولم يضف صلاحيات، ولم يغيّر قاعدة البيانات أو Railway. لا يجوز اعتباره إغلاقاً لتدقيق الاعتماديات أو قبولاً للإطلاق حتى تجتاز كل بوابات CI والاختبارات الأصلية المطلوبة.
