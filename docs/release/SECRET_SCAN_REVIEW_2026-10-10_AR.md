# مراجعة فحص الأسرار — P0.05

**التاريخ:** 2026-10-10
**النطاق الحالي:** الملفات المتتبعة وغير المتجاهلة في شجرة العمل، وليس سجل Git الكامل بعد.

شُغلت أداة Gitleaks الرسمية `8.30.1` بعد التحقق من SHA-256 لملف الإصدار. فحصت الأداة 887 ملفاً، وسجلت نتيجتين من قاعدة `generic-api-key`:

- `backend/app/infrastructure/ai/ai_gateway.py:28` يطابق اسم متغير `HUGGINGFACE_API_KEY` في حلقة بحث عن متغيرات البيئة، ولا يحتوي السطر على قيمة مفتاح.
- `engine/voice/VoiceSynthesizer.ts:73` يطابق ثابت `TrustedClientToken` الخاص ببروتوكول Edge Read Aloud. السياق المفتوح المصدر يصف Edge TTS بأنه يعمل دون مفتاح API؛ لذلك هذه ليست مفتاح حساب خاصاً بالمشروع، لكنها قيمة ثابتة مرتبطة بواجهة غير رسمية قد تتغير أو ترفض الطلبات. أظهر بلاغ عام عن Edge TTS أخطاء 403 على WebSocket ثم أشار مالك المشروع إلى إصلاح متعلق بتحديث المكتبة [2] [3].

لم يُعثر على مفتاح خاص أو token حساب في مسح الملفات الحالي، كما لم يلتقط فاحص الأنماط المحلي مفاتيح معروفة. هذا **لا يثبت** خلو سجل Git من الأسرار. محاولة قراءة GitHub Secret Scanning Alerts رُفضت بصلاحيات التكامل (403)، لذا لم تُقرأ أي alerts من GitHub.

قبل رفع الفرع العام، يلزم مسح فرق commits بين `origin/main` والفرع باستخدام `gitleaks git`؛ لم يجر هذا بعد لأن التغييرات النهائية غير ملتزمة وقت كتابة هذا المستند. يجب ألا يُعرض تقرير Gitleaks الخام أو أي قيمة منه. وبالنسبة لجاهزية الإنتاج، يعتمد Edge TTS على endpoint غير رسمي؛ نوصي أن تبقى طبقة الصوت قابلة لاستبدال المزود، وأن يعتمد الإطلاق العام على مزود مدعوم بعقد/واجهة مستقرة مع fallback واختبار 403/انقطاع.
