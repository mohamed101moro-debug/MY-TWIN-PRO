# مراجعة فحص الأسرار — P0.05

**التاريخ:** 2026-10-10
**النطاق:** شجرة العمل وسجل commits الجديدة في فرع التكامل مقارنةً بـ `origin/main`.

شُغلت أداة Gitleaks الرسمية `8.30.1` بعد التحقق من SHA-256 لملف الإصدار. فحصت الأداة 887 ملفاً في شجرة العمل، وسجلت نتيجتين من قاعدة `generic-api-key`:

- `backend/app/infrastructure/ai/ai_gateway.py:28` يطابق اسم متغير `HUGGINGFACE_API_KEY` في حلقة بحث عن متغيرات البيئة، ولا يحتوي السطر على قيمة مفتاح.
- `engine/voice/VoiceSynthesizer.ts:73` يطابق ثابت `TrustedClientToken` الخاص ببروتوكول Edge Read Aloud. يصف مشروع Edge TTS المفتوح استخدام الخدمة دون API key؛ لذلك هذه ليست مفتاح حساب خاصاً بالمشروع، لكنها قيمة ثابتة مرتبطة بواجهة غير رسمية قد تتغير أو ترفض الطلبات. أظهر بلاغ عام أخطاء 403 على WebSocket ثم متابعة إصلاح عبر تحديث المكتبة [2] [3].

بعد commit `3a8f4f0b416ee9ad8f8df87d3e4a8c70aa8b657c`، اكتمل `gitleaks git` على الفرق `origin/main..HEAD` بنتيجة **0 findings**. لم يُعثر في الإضافات الجديدة إلى التاريخ على مفتاح خاص أو token حساب. فاحص الأنماط المحلي لم يلتقط مفاتيح معروفة أيضاً.

محاولة قراءة GitHub Secret Scanning Alerts رُفضت بصلاحيات التكامل (403)، لذلك لم تُقرأ أي alerts من GitHub. نتيجة الفحص المحلي تخص commits الجديدة والشجرة المفحوصة، ولا تدّعي حالة التنبيهات الموجودة في GitHub أو سلامة بيانات تشغيل Railway/Supabase.

بالنسبة لجاهزية الإنتاج، يعتمد Edge TTS على endpoint غير رسمي؛ نوصي أن تبقى طبقة الصوت قابلة لاستبدال المزود، وأن يعتمد الإطلاق العام على مزود مدعوم بواجهة مستقرة مع fallback واختبار 403/انقطاع.
